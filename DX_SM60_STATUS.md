# DirectX Shader Model 6.0 Status

## Date: 2025-11-16

## Summary
Updated shader compilation from SM 5.1 to SM 6.0 to support modern shader models. WARP supports up to SM 6.2, Proton/vkd3d supports up to SM 6.6+.

## Changes Made

### 1. Shader Model Update (build.rs)
- Changed from `vs_5_1`/`ps_5_1` to `vs_6_0`/`ps_6_0`
- Added `-Qstrip_reflect` flag to reduce DXIL size
- Rationale: SM 6.0 provides modern features while maintaining compatibility with WARP (max SM 6.2)

### 2. Shadow Map Made Optional (forward_simple.hlsl)
- Added `#if defined(ENABLE_SHADOWS)` preprocessor guards
- Shadow map texture (t1) and shadow sampler (s2) only declared when ENABLE_SHADOWS is defined
- Shadow calculation code also guarded
- Rationale: Avoid requiring shadow resources when they aren't being used

### 3. Sampler Register Fix
- Changed baseColorSampler from `s1` to `s0` in HLSL
- Updated DirectX root signature static samplers accordingly
- shadowSampler moved from `s2` to `s1`
- Rationale: vkd3d-proton expects samplers to start at s0

## Current Status

### ✅ Working
- Vulkan backend: Compiles and runs successfully with SM 6.0 shaders
- HLSL shaders compile to both SPIR-V (for Vulkan) and DXIL (for DirectX)
- Shader files generated:
  - forward_simple.{vert,frag}.{spv,dxil}
  - shadow_map.{vert,frag}.{spv,dxil}

### ❌ Failing
- DirectX/Proton: DXIL->SPIR-V conversion fails
- Error: `vkd3d-proton:vkd3d_compile_shader_stage: Failed to compile shader, vkd3d result -3`
- VKD3D_ERROR_INVALID_SHADER (-3) indicates the DXIL bytecode is rejected during conversion

## Root Cause Analysis

The vkd3d-proton layer (which translates D3D12 to Vulkan) attempts to convert DXIL bytecode to SPIR-V at runtime. The conversion is failing, likely due to:

1. **Resource Binding Mismatch**: The DXIL declares resources that don't match what vkd3d-proton expects in the descriptor layout
2. **Missing Resources**: Even with ENABLE_SHADOWS undefined, there may be implicit resource requirements
3. **DXIL Format Issues**: The DXIL generated by DXC may not be fully compatible with vkd3d-proton's converter

## Attempted Fixes

1. ❌ Disabled validation with `-Vd` flag
2. ❌ Changed from SM 6.2 to SM 6.0  
3. ❌ Made shadow resources optional with preprocessor
4. ❌ Fixed sampler register numbering (s0 instead of s1)
5. ❌ Added reflection stripping with `-Qstrip_reflect`

## Next Steps

- This would confirm if the issue is with our DXIL or vkd3d-proton compatibility

### Option B: Simpler Shader
- Create minimal test shader with only basic resources (tested, created test_simple.hlsl)
- If minimal shader works, incrementally add features to find breaking point

### Option C: Alternative Approach
- Use D3DCompile with HLSL source compilation instead of pre-compiled DXIL
- This is what the legacy triangle shader path does
- May have better vkd3d-proton compatibility

### Option D: Resource Binding Investigation
- Dump DXIL resource tables to see what's declared
- Compare with root signature to find mismatch
- Tools: `dxc -dumpbin` or `dxil-spirv` converter directly

## Shader Register Layout

### Current Layout (without ENABLE_SHADOWS)
- `b0`: LightingUniforms (CBV)
- `b1`: ShadowUniforms (CBV) - still present but shadow texture not used
- `b2`: PushConstants (root constants)
- `t0`: baseColorTexture (SRV)
- `s0`: baseColorSampler (static sampler)

### With ENABLE_SHADOWS (future)
- `b0`: LightingUniforms (CBV)
- `b1`: ShadowUniforms (CBV)
- `b2`: PushConstants (root constants)
- `t0`: baseColorTexture (SRV)
- `t1`: shadowMap (SRV)
- `s0`: baseColorSampler (static sampler)
- `s1`: shadowSampler (comparison sampler)
