## Technical Details

### Pass Execution Flow

1. Backend's `execute_graph()` receives RenderGraph + CompiledGraph
2. For each pass in execution order:
   - Insert barriers if needed
   - Look up pass definition from RenderGraph
   - Create backend-specific execution context (e.g., VulkanPassContext)
   - Call pass callback with context
   - Pass uses context methods to bind buffers and draw

### Context Design

The context uses raw pointers (`*const c_void`) for buffer references to avoid lifetime issues across the trait boundary. Backends are responsible for safely casting these back to their buffer types.

### Safety

- Buffer pointer casting is done safely within backend implementations
- Vulkan device pointer is stored as raw pointer to avoid lifetime issues
- All unsafe operations are contained within backend implementations

## Example Usage (Ready to Implement)

```rust
struct VertexBufferTrianglePass {
    vertex_buffer: Box<dyn Buffer>,
}

impl PassCallback for VertexBufferTrianglePass {
    fn execute(&self, context: &mut dyn PassExecutionContext) {
        // Bind vertex buffer
        let buffer_ptr = self.vertex_buffer.as_ref() as *const _ as *const std::ffi::c_void;
        context.bind_vertex_buffer(0, buffer_ptr, 0).unwrap();
        
        // Draw 3 vertices
        context.draw(3, 1, 0, 0).unwrap();
    }
}
```
