# M8.3: API Cleanup - Remove Duplicate Methods

## Issue

GraphicsBackend trait has these methods that duplicate PassExecutionContext:
- `bind_vertex_buffer()`
- `bind_index_buffer()`
- `draw()`
- `draw_indexed()`

These are **never used** and **shouldn't exist** on GraphicsBackend.

## Why They Exist

Historical reasons - M8.2 added them before render graph execution was complete.

## The Fix

### Remove from GraphicsBackend trait:
```rust
// DELETE THESE from backends/mod.rs
fn bind_vertex_buffer(&mut self, binding: u32, buffer: &dyn Buffer, offset: u64) -> Result<()>;
fn bind_index_buffer(&mut self, buffer: &dyn Buffer, offset: u64, index_type: IndexType) -> Result<()>;
fn draw(&mut self, vertex_count: u32, instance_count: u32, first_vertex: u32, first_instance: u32) -> Result<()>;
fn draw_indexed(&mut self, index_count: u32, instance_count: u32, first_index: u32, vertex_offset: i32, first_instance: u32) -> Result<()>;
```

### Remove implementations:
- VulkanBackend (currently returns error)
- WgpuBackend (currently returns error)
- DirectXBackend (currently returns error)

### Keep ONLY in PassExecutionContext:
PassExecutionContext already has these properly implemented for render graph usage.

## Benefits

✅ Clear separation of concerns
✅ Removes confusion
✅ Prevents misuse (trying to call draw() on backend directly)
✅ Cleaner API

## Implementation

1. Remove methods from `GraphicsBackend` trait in `backends/mod.rs`
2. Remove stub implementations from all backends
3. Verify render graph still works (it uses PassExecutionContext)
4. Update any documentation
