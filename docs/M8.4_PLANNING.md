## Architecture

### Data Flow
```
Image File (PNG/JPG)
    └─> TextureLoader::load_from_file()
         └─> LoadedImage { width, height, data: RGBA8 }
              └─> Backend::create_texture(desc, initial_data)
                   ├─> Vulkan: Staging buffer → vkCmdCopyBufferToImage
                   ├─> wgpu: Queue::write_texture
                   └─> DirectX: Upload heap → CopyTextureRegion
                        └─> GPU Texture Resource
                             └─> Bind to shader via BindGroup
                                  └─> Sample in fragment shader
```

### Backend-Specific Considerations

#### Vulkan
- Need staging buffer for texture upload
- Image layout transitions: UNDEFINED → TRANSFER_DST → SHADER_READ_ONLY
- Pipeline barriers for synchronization
- Combined image/sampler descriptors

#### wgpu
- Simple `Queue::write_texture()` API
- Separate texture and sampler bindings
- Automatic synchronization

#### DirectX 12
- Upload heap for staging
- CopyTextureRegion command
- SRV (Shader Resource View) creation
- Separate texture and sampler descriptors in root signature

## Risks

1. **Backend Complexity:** Texture upload differs significantly between backends
   - *Mitigation:* Follow established patterns from buffer uploads (M8.2)

2. **Synchronization:** Texture uploads need proper barriers/fences
   - *Mitigation:* Use existing command buffer patterns, test thoroughly

3. **Format Compatibility:** Different backends support different texture formats
   - *Mitigation:* Start with RGBA8, most widely supported format

4. **Visual Regression:** Changes might affect existing rendering
   - *Mitigation:* Run visual tests after each phase
